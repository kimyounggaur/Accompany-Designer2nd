### 2단계. 화면 틀과 데이터 보호
- ✅ P2-1 화면 틀(AppShell): 상단 바 107px(1280~1599px)·59px(1600px 이상), 1280×720에서 트랙 3개 보임, 오른쪽 패널 칸별 접기
  - 설계와 다르게 한 점 ① 오른쪽 패널 최소 폭을 288px가 아니라 **320px**로 둠: 딜레이·리버브·EQ 장비 화면이 288px에서 잘리거나 글자가 깨짐(기존 고정 폭도 320px). 장비 화면이 폭에 맞춰 줄어들게 하는 일은 P5-0.
  - ② 클립 칸에 이미 있던 소스 BPM·스트레치·속도 표시는 상단 바의 WARP 묶음(원본 BPM·WARP·배속)과 같은 값이라 하나로 합침(라벨은 "원본 BPM").
  - ③ "화면 배치가 바뀌었습니다" 한 번 안내는 안내 통로가 필요하므로 P2-2에서 함.
  - 알려진 기존 문제: 패널 폭 346px 이하에서 딜레이 장비의 5번째 노브가 오른쪽에서 잘림(P5-0).
- ✅ P2-2 안내 통로 하나: `commandMessage` 50곳·`setStatus` 26곳·`window.confirm` 2곳 → 0건. 오류(빨강·닫을 때까지)·경고(8초)·완료(3초)는 토스트, 정보는 상태 줄만, 도구·스냅 같은 상태 표시는 안내 없음. 같은 안내가 연달아 오면 ×N.
  - 스토어 함수는 문구 대신 `CommandResult`를 돌려주고, 문구는 `src/app/actions.ts`가 정해 `notify()`로 보냄. 새 확인창(`ConfirmDialog`)이 트랙 삭제·프로젝트 불러오기의 브라우저 기본 확인창을 대체.
  - 설계와 다르게 한 점 ① 결과 반환을 `state/commands/*`(P3-1) 대신 지금의 `useDawStore` 안에서 함(P3-1에서 그대로 옮김). ② "화면 배치가 바뀌었습니다"는 `notify` 통로가 아니라 별도 1회 카드(`LayoutNotice`)로 구현: 상태 줄의 복구 안내를 덮지 않기 위해. [닫기]=이번만 숨김, [다시 보지 않기]=기억.
  - 덧붙인 개선: 복사할 클립이 없을 때 "클립 0개 복사됨" 대신 안내, 여러 파일 중 일부가 실패했을 때 "N개 파일 업로드 완료"라고 거짓 안내하던 것을 경고로 바꿈.
  - 남은 일: 문구가 아직 `app/actions.ts`·`App.tsx`에 있음 → P2-3에서 `i18n/ko.ts`로. 영어 오류 원문 변환도 P2-3.
- ✅ P2-3 사용자 문구를 한곳에: 화면 글자의 영어 라벨 47곳 → 0곳(검사 스크립트가 `npm run check`·CI에서 지킴). 안내·확인창·오류 문구는 `src/i18n/ko.ts`로 모으고, 브라우저 영어 오류는 `src/services/errors.ts`의 `toUserMessage`가 한국어로 바꿈(원문은 토스트의 접힌 "자세히 보기"에만).
  - 라벨 교체: 트랙 믹스·음소거·솔로·볼륨·팬, 이퀄라이저(저음·중저음·중고음·고음·프레즌스), 컴프레서(기준 음량·압축 비율·반응 시간·회복 시간), 이펙트 랙(이퀄라이저·컴프레서·딜레이·리버브, 켜짐/꺼짐), 리버브·딜레이 장비 화면, 레벨 미터, 트랙 머리(녹음 대기·음소거·솔로·볼륨).
  - 설계와 다르게 한 점 ① `ko.ts`에는 안내·확인창·오류 문구와 예전에 영어였던 라벨을 모았고, JSX에 이미 한국어로 적힌 정적 글자(단추 이름 등 수백 곳)는 그대로 둠. 새 영어가 들어오지 못하게 검사 스크립트가 지킴. ② 검사 범위를 `.tsx`만이 아니라 `src/**/*.ts(x)` 전체(JSX 글자, `aria-label`·`title`·`placeholder`·`alt`, 객체의 `label`·`title`·`description` 값)로 넓힘. 허용: eq·bpm·wav·mp3·rms·warp(두 글자 단위 dB·Hz·ms·L·R은 세 글자 기준에 걸리지 않음). ③ 변환표에 두 줄 추가(프로젝트 파일 JSON 문법 오류, 프로젝트 안 음원 해독 오류). 이 앱이 던진 한국어 사유는 "○○ 실패: 사유"로 그대로 보이고, 알 수 없는 오류는 "○○ 실패: 예상하지 못한 문제가 생겼습니다."(무엇이 실패했는지 앞에 붙임). ④ 트랙 머리의 "녹음 대기·음소거·솔로"는 12px로 줄여 220px 머리 안에 한 줄로 들어가서(아이콘+이름표로 바꿀 필요 없음) 글자만 씀.
  - 덧붙인 개선: 이펙트 랙이 따로 갖고 있던 메시지 줄을 공용 안내 통로로 합침. 카운트인 취소를 영어 문자열 비교 대신 전용 오류 클래스로. 배경과 같은 색이라 안 보이던 글자(이펙트 랙 이름 대비 1.05:1, 레벨 미터 이름·dB 1.0~1.8:1, 컴프레서 보조 글자 등)를 `src/styles/legibility.css`로 보정: 인스펙터·트랙 머리에서 대비 3:1 미만 34곳 → 1곳(장식용 "RD" 마크).
  - 남은 일: 장비 화면 라벨 글자가 5~9px로 작음 → P5-0(공용 조작부)·P6-2(접근성). 대비 4.5:1 미만 8곳(작은 라벨 글자)도 P6-2. 속도 표시의 `ms`·`Hz`가 CSS 대문자 변환으로 `MS`·`HZ`로 보임 → P6-1(CSS 정리).
- ✅ P2-4 자동 저장을 서비스로 분리: `App.tsx`의 `indexedDB`·`saveAutosave`·`beforeunload` 4곳 → 0곳(799줄 → 707줄). 저장·복구·옛 데이터 이전은 `src/services/persistence/`(`db.ts`·`autosave.ts`·`scheduler.ts`·`projectRecord.ts`·`assetHash.ts`), 앱 시작 때 하는 일은 `src/app/bootstrap.ts`.
  - 저장소(IndexedDB v2): `projects`(프로젝트 id별 기록, 최근 5개) · `assets`(음원 SHA-256 해시별 1개 — 같은 음원은 몇 번 올려도, 프로젝트가 여러 개여도 한 번만) · `peaks`(P4-3용, 비어 있음) · `meta`(`lastProjectId`). 문서·음원·"마지막 프로젝트" 표시는 한 트랜잭션이라 저장 공간이 모자라 실패해도 이전 기록이 그대로 남음.
  - 옛 자동 저장(v1)은 처음 열 때 새 구조로 옮기고 옛 칸을 지움(복사와 삭제가 한 트랜잭션). 옛 데이터를 읽을 수 없으면 지우지 않고 오류로 알림. 새 형식의 기록이 이미 있으면 새 쪽이 더 최신이라 옮기지 않음.
  - 저장 시점: 바뀐 뒤 1.2초 / 탭을 숨길 때(`visibilitychange`)·페이지를 떠날 때(`pagehide`)는 바로 시작(끝난다는 보장은 없음, 최선) / 녹음 중에는 저장하지 않고 녹음이 끝난 뒤. 닫기 경고는 저장 안 된 변경이 있거나 녹음 중일 때만.
  - 상태 줄 오른쪽 표시: "저장 중…" · "자동 저장됨 02:41"(복구했을 때는 그 기록의 저장 시각) · "자동 저장 실패"(빨강) + 오류 토스트의 [프로젝트 파일로 저장] 단추. 실패하면 "저장 안 된 변경"으로 남아 닫을 때 경고하고, 공간이 생기면 다음 변경부터 다시 저장.
  - 저장 공간: 음원을 처음 저장한 뒤 `navigator.storage.persist()`를 한 번 요청, `estimate()`가 80%를 넘으면 세션당 한 번 경고.
  - 설계와 다르게 한 점 ① 프로젝트 기록에 설계의 `{schemaVersion, doc, updatedAt}` 외에 `assetHashes`(음원 id → 해시)를 둠: 복구 때 해시를 다시 계산하지 않고 음원을 바로 찾기 위해. ② 프로젝트 기록을 한 칸 덮어쓰기(v1) 대신 최근 5개 보관 + 어느 기록도 쓰지 않는 음원 자동 정리(새 프로젝트를 시작해도 바로 이전 작업이 남음). ③ `persist()`는 음원을 올리는 순간이 아니라 그 음원이 처음 저장된 직후에 요청. ④ 녹음 중에도 문서는 바뀜(클립이 자람): 저장을 미루고 "녹음 중에 바뀜"을 기억했다가 끝나면 한 번 예약, 카운트인만 하고 취소하면 저장하지 않음. ⑤ 상태 표시는 안내 문구 줄과 겹치지 않게 따로 둠. ⑥ `autosave.ts`는 화면·오디오 엔진을 몰라서, 현재 프로젝트·음원·변경 알림은 `bootstrap.ts`가 넘겨 줌(`app/projectSnapshot.ts`·`app/projectFile.ts`가 함께 생김). ⑦ 해시를 못 구하는 환경(보안 연결이 아닌 주소)에서는 해시 대신 음원 id 키로 저장(저장은 되지만 같은 음원을 한 번만 담지는 못함).
  - 덧붙인 개선: 복구를 기다리는 사이 사용자가 바꾼 내용도 이제 저장 대상(예전에는 다음 변경 전까지 저장되지 않음). 마커만 바꾼 경우도 복구가 덮어쓰지 않음.
  - 시험: 단위 75개(새 19개: 해시·정리 규칙·변경 감시·예약기·저장 공간 점검) · e2e 54개(새 9개: 옛 v1 데이터 복구 후 v2로 이전, 같은 음원 한 번만 저장, 탭 숨김·페이지 떠남 즉시 저장, 녹음 중 저장 안 함 + 닫기 경고 + 끝난 뒤 저장, 저장 끝난 뒤 경고 없음, 저장 공간 부족 오류와 파일 저장 단추, persist·80% 경고). 새 라이브러리(fake-indexeddb 등) 없이 실제 Chrome의 IndexedDB로 확인.
  - 되돌릴 때 주의: 한 번 v2로 올라간 브라우저의 데이터베이스는 v1 코드가 열 수 없음(IndexedDB는 버전을 낮출 수 없음). P2-4를 되돌리면 그 브라우저의 자동 저장은 사이트 데이터를 지우기 전까지 동작하지 않으므로, 되돌리기 전에 프로젝트 파일(.json)로 보관하도록 안내할 것. 프로젝트 파일 형식은 바뀌지 않았음.
  - 참고: 이 시험 환경(리눅스 Chrome)에서는 파일 이름에 한글이 있으면 내려받은 파일 이름이 `download`로 정해짐(`새-세션.json` → `download`). 앱 코드는 그대로이고 운영체제의 글자 처리 문제로 보이나 Windows·macOS에서는 확인하지 못함.

### 3단계. 재생 구조 교체
- ✅ P3-0 안전망 보강: 화면 부품에서 오류가 나면 빈 화면 대신 "문제가 생겨 화면을 다시 그려야 합니다. 작업은 자동 저장되어 있습니다." + [새로고침] + [오류 내용 복사](접힌 오류 내용 포함)가 뜸(`app/ErrorBoundary.tsx`). window 오류·처리되지 않은 약속 거절은 `notifyError`로 알림("동작 실패: 예상하지 못한 문제가 생겼습니다.", 원문은 접힌 "자세히 보기"). 주소에 `?probe=1`이 있으면 마스터 출력 뒤에 측정 프로브가 붙어 튐(`jumps`)·끊김(`gaps`)·`peak`·`longestGapMs`를 0.1초마다 `window.__probe`에 둠(`audio/worklets/probe.worklet.ts`, `audio/probe.ts`).
  - 기준값: 지금 엔진에서 `?probe=1`로 조작 없이 3초 재생 → **튐 0회·끊김 0회**(보고서의 "잘 되어 있는 점"과 같은 값). 3단계의 나머지 단위는 이 값이 유지되는지로 확인함.
  - 설계와 다르게 한 점 ① 연결 위치가 `src/app/main.tsx`가 아니라 지금 구조의 `src/main.tsx`. ② 끊김은 첫 소리가 난 뒤의 무음만 세고(재생 전 무음은 제외), 재생 직전에 0으로 되돌리는 `window.__probeReset()`을 둠. ③ 프로브 코드는 `?probe=1`일 때만 내려받는 별도 파일이라 일반 사용자의 번들에는 들어가지 않음. ④ 시험용 주소 `?crash=1`(그리는 즉시 오류)을 추가해 오류 화면을 확인할 수 있게 함. 두 주소는 README "개발용 주소"에 적음.
