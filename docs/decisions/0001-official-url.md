# 0001 공식 주소와 브랜치

- 상태: 확정 (2026-11-23, 설계서 추천안 채택 — 소유자가 "스스로 승인하며 진행"으로 위임)
- 결정: Vercel 주소 하나만 공식으로 쓴다. 기본 브랜치는 `master`. GitHub Pages는 끈다. codex 브랜치가 추가한 `.github/workflows/pages.yml`과 `build:pages` 스크립트는 삭제한다.
- 이유: 주소가 둘이면 어느 쪽이 최신인지 어긋난다(보고서 A1). 점검 시점에 GitHub 기본 브랜치 main은 4월 코드(ec5216d)였고 master는 6월 23일(d79a228)에서 멈춰 있었으며, 어느 쪽이 운영 주소로 나가는지는 확인하지 못했다(설계서 §2.2).
- 영향: P1-1(빌드 표시), P1-2(Pages 정리). Pages 주소는 더 이상 열리지 않는다.
- 실행 상태: 코드 쪽(빌드 표시, 워크플로 삭제)은 이 저장소에서 처리한다. **Vercel Production Branch를 master로 바꾸기, GitHub 기본 브랜치를 master로 바꾸기, Pages 끄기, 옛 main 보관 태그**는 대시보드 작업이라 아직 실행하지 않았다(소유자 계정 필요). 이 결정의 수용 기준은 "운영 주소의 빌드 표시 = master 최신 커밋"이다.
- 다르게 정하면: Pages를 유지할 경우 P1-2 대신 두 주소의 빌드 표시를 맞추는 검사를 넣는다.
